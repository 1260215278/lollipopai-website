# 发行中心 · 收益明细「历史结算 / 总收益」两列 — 前端对接

> 对接接口：`GET /publisher/settlement/earnings`（收益详情表格数据源）
> 背景：设计稿收益详情表右侧的「历史结算」「总收益」两列此前是前端占位假数据（各行差值恰好 ¥3000/4000/5000、总收益≠本月+历史即为 mock）。本次后端已在 earnings 每行补齐真实值，前端可去掉 mock 接真值。
> 变更类型：**纯后端**（`PublisherEarningsDao.xml` 的 `pageEarnings` 加两列子查询），无 DDL、无新错误码。

## 每行新增字段

```json
{
  "totalCreatorUsd": 200.91,
  "historySettledUsd": 13.00
}
```

| 字段 | 界面列 | 口径 |
|---|---|---|
| `totalCreatorUsd` | 总收益 | 该剧**全期**创作者累计应得（`SUM(publisher_earnings.creator_usd)`，account+course 全期），含 待结算 + 结算中 + 已结算。与账户总览 `totalCumulativeUsd` 同口径。 |
| `historySettledUsd` | 历史结算 | 该剧累计**已打款**结算金额（结算单 `status=3` 的 `publisher_settlement_item.creator_usd` 之和）。与账户总览「已结算」/结算概况图表「status=3 口径」一致。 |

## 关键说明

- **币种是 USD**，与 earnings 已有的 `creatorUsd`/`grossUsd` 及账户总览（`currency:"USD"`）完全一致。界面显示 ¥ 由前端沿用现有 USD→CNY 换算逻辑（和「本月结算金额」同一套换算），后端不额外返 CNY。
- **两列是剧级全期常量**，**不随月份 Tab / `startDate`·`endDate` 筛选变化**——同一部剧在任意月份视图下这两个值相同，只有「本月结算金额」(`creatorUsd`) 随所选月份变。
- 恒有 `totalCreatorUsd >= historySettledUsd`（已结算是总收益的子集）。差额 = 尚未打款部分（待结算 + 结算中）。
- 若该剧从未结算过，`historySettledUsd` 为 `0.00`（非 null）；`totalCreatorUsd` 至少等于其历史各月收益之和。

## 与「本月结算金额」的关系

| 列 | 字段 | 随月份变 |
|---|---|---|
| 本月结算金额 | `creatorUsd` | 是（当前行 `earnDate` 所属月的创作者应得） |
| 历史结算 | `historySettledUsd` | 否（剧级全期已打款累计） |
| 总收益 | `totalCreatorUsd` | 否（剧级全期总应得） |
