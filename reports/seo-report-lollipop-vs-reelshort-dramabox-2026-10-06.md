### 5.4 对比表 Schema 建议
- **现状**：schema.org 没有一等公民的"ComparisonTable"类型，Google 也不会直接消费对比表 JSON-LD 来生成富媒体；但 **干净的语义化 `<table>` 是表格型 Featured Snippet 的主要抓取源**。
- **结构端（必做）**：把 H2一 与 H2六 的 Markdown 表渲染为带 `<caption>`、`<th scope="col">`、`<th scope="row">` 的 HTML 表，列名用实体全名（维度 / Lollipop Drama / ReelShort / DramaBox），不要合并或缩写。
- **Schema 端（可选增强）**：可将三个平台分别标记为 `SoftwareApplication`（有 `name`/`description`/`offers` 近似项），或把整张表作为 `WebPage` 的 `mainEntity` 指向 `Table` 类型。示例（轻量版）：
```json
{
  "@context": "https://schema.org",
  "@type": "Table",
  "name": "Lollipop Drama vs ReelShort vs DramaBox 2026 对比",
  "about": "短剧平台分成、AI 工具、内容模式与出海能力对比",
  "mainEntity": "https://lollipop.im/blog/reelshort-alternative-lollipop-vs-reelshort-dramabox-2026"
}
```
> 务实建议：优先保证**语义化 HTML 表 + FAQPage + Article** 三项；对比表 Schema 属锦上添花，不做也不影响排名与摘要捕获。

## 6. Featured Snippet 捕获建议

**机会类型**：对比表型 Snippet（"X vs Y vs Z"类查询）+ 段落摘要（核心答案块）。

1. **核心答案句前置且独立**（高优先级）
   - 现状：H2一 L22 是一段 60+ 字加粗长句，信息全但偏长，不利于被直接摘录为 ≤50 字答案。
   - 建议：在 H2一 开头**单独抽出一句 ≤45 字**的答案句（保留原长段作展开）：
     > "如果你是想创作并高分成变现 AI 短剧的创作者，Lollipop Drama 是目前唯一内置 AI 工具且给 80% 分成的 ReelShort 替代品。"
   - 该句同时命中 GEO/AEO 的"ReelShort alternative"引用句式，且与 llms.txt 表述一致。

2. **对比表字段命名优化**（中优先级）
   - 给两张表加 `<caption>`（如"2026 三大短剧平台核心差异对比"），列头用全名；行头（维度列）用 `<th scope="row">`。
   - "具象化实例"表（每月 $1000）极适合捕获"ReelShort 创作者分成多少"的段落/表摘要，保留并置于 H2二 显眼处（当前已在，保持）。

3. **定义式短答**（低优先级）
   - 在 H2三 或 H2一 补一句"什么是 AI 原生短剧平台？——把 AI 创作工具内置、让创作者从生成到分发一站式完成的平台"，可捕获"AI 原生 短剧 是什么"类定义摘要。
