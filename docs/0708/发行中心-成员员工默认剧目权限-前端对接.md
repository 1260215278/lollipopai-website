# 发行中心 · 成员员工默认剧目权限 — 前端对接（2026-07-07）

> 对应前端反馈《member-default-course-permission-backend-feedback-2026-07-07》。
> 本次**纯后端权限口径调整**，**无接口路径/请求体/响应体结构变更**，无新增字段，无 DDL。前端按下述口径显隐即可。

## 一句话结论

员工（`role=3`）默认具备 `COURSE_VIEW_ASSIGNED`，**可进入上剧中心、创建并送审新剧、看账户名下全部剧目**；但**不能上/下架**（`shelf` 仍需 `COURSE_MANAGE`，仅超管/管理员）。手动「分配剧目给员工」已废弃，前端无需再调。

---

## 一、角色 × 权限对照（后端固定，代码不建表）

| 角色 | code | 关键权限 | 能做 | 不能做 |
|---|---|---|---|---|
| 超管 | 1 | 全部 | 全部 | — |
| 管理员 | 2 | `COURSE_MANAGE` + `COURSE_VIEW_ASSIGNED` + `DASHBOARD_VIEW` … | 上剧、上下架、看全部剧、看收益 | 提现、成员管理 |
| **员工** | **3** | **`DASHBOARD_VIEW` + `COURSE_VIEW_ASSIGNED`** | **进上剧中心、创建/送审新剧、看账户全部剧与基础数据** | **上下架(shelf)、结算/合同/成员管理** |

- `GET /publisher/member/me` → `permissions` 对员工**稳定含** `"COURSE_VIEW_ASSIGNED"`（还有 `"DASHBOARD_VIEW"`）。前端可据此放行「上剧中心」「上新剧」入口。
- `GET /publisher/member/roles` → 员工角色卡里 `COURSE_VIEW_ASSIGNED.allowed = true`（成员管理页权限说明用）。

> 前端不必再本地把 `role=3` 硬编码为「有 `COURSE_VIEW_ASSIGNED`」，直接用 `me()` 返回的 `permissions` 即可（前后端同源，口径一致）。

---

## 二、上剧接口权限分层（本次核心变化）

**员工可调用（`COURSE_VIEW_ASSIGNED`，即创建/编辑草稿并送审）：**

| 接口 | 说明 |
|---|---|
| `POST /publisher/course/saveBasic` | Step1 暂存基本信息 |
| `POST /publisher/course/saveEpisode` | Step2 暂存/上传单集 |
| `POST /publisher/course/deleteEpisode` | Step2 移除单集（草稿/驳回态） |
| `POST /publisher/course/publish` | Step3 发布配置并送审 |
| `POST /publisher/course/saveHighlight` | 挂载/移除高光时刻视频 |
| `POST /publisher/course/clearDraft` | 清空草稿 |
| `GET /publisher/course/uploadTemplate` | 批量录入模版下载 |
| `POST /publisher/course/upload` | 上剧文件上传（封面/视频/文档） |

**员工不可调用（`COURSE_MANAGE`，仅超管/管理员）：**

| 接口 | 说明 |
|---|---|
| `POST /publisher/course/shelf` | **上架 / 下架** |

- 员工若命中不可用接口 → 由 `@PublisherPerm` 拦截返回无权限（沿用现有鉴权失败响应，非本次新增码）。**前端应对员工隐藏「上/下架」按钮**，避免点了报错。
- 只读类（列表/详情/统计/剧集/各种候选项：`list`/`detail`/`stats`/`episodes`/`draft`/`priceRule`/`revenueOptions`/`labels`/`classifications`）仍为 `DASHBOARD_VIEW`，员工可用。

---

## 三、员工可见剧目范围 = 账户名下全部剧目

- 口径：**员工可见并可进入本发行账户名下的全部剧目**（不再按「手动分配」过滤）。
- 已统一的读接口（对员工一致返回「账户全部」）：
  - `GET /publisher/course/list`、`GET /publisher/course/detail`
  - `GET /publisher/dashboard/overview`、`/trend`、`/ranking`、`/playCompare`
- 变化点：此前 dashboard 对员工按「已分配剧集」过滤，移除手动分配后会导致员工看到**空数据**；现已改为不过滤，与 course 列表口径一致。

> 验收「员工进入 `/distribution/content` 无需管理员分配即可看到剧目列表」→ 满足。

---

## 四、废弃接口（前端**不要再调用**）

以下三个「分配剧目给员工」接口已 `@Deprecated`（后端保留、仍 `MEMBER_MANAGE` 鉴权，但不参与任何读路径，也不作为员工基础可见权限的前置）：

- `GET /publisher/member/course/list`
- `POST /publisher/member/course/assign`
- `POST /publisher/member/course/unassign`

前端已移除「分配」按钮/弹窗即可，无需为员工基础可见权限调用它们。

## 五、前端改动清单（建议）

1. 成员列表：移除「分配」按钮及弹窗（已做）；不再调用上述三个废弃接口。
2. 上剧中心 / 上新剧入口：对 `role=3`（或 `me().permissions` 含 `COURSE_VIEW_ASSIGNED`）放行。
3. 剧目管理页：对员工**隐藏「上架 / 下架」**（及其它 `COURSE_MANAGE` 级管理动作）。
4. 成员管理 · 员工角色权限说明：`COURSE_VIEW_ASSIGNED` 展示为「允许」（后端 `roles()` 已返回 `allowed=true`）。
