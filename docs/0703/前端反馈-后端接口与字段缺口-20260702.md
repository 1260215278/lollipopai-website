## 一、缺接口

### P0-1. 当前登录成员身份接口（角色驱动 UI 显隐）

**问题**：登录换取发行 token 后（`POST /publisher/login/byAppToken`），前端**无法得知当前成员的角色**（超管/管理员/员工）。

设计稿「角色权限说明」明确了不同角色的可见范围：

| 角色 | 不可见模块 |
|---|---|
| 管理员 | 成员管理、提现操作 |
| 员工 | 结算中心、合同管理、成员管理、账号设置 |

前端需要按角色**隐藏侧边栏入口和页面功能**，目前只能等用户点进页面后吃到 `403335`（无该操作权限）toast，体验差且泄露入口。

**建议**：新增 `GET /publisher/member/me`，或在 `byAppToken` 响应 / 任一现有聚合接口中附带：

```jsonc
{
  "memberUserId": 123,
  "role": 2,            // 1超管 / 2管理员 / 3员工
  "roleName": "管理员",
  "permissions": ["dashboard", "course", "settlement_view"]  // 可选，与 /member/roles 的 key 对齐
}
```

### P1-2. 收益明细「有数据的月份列表」

**问题**：收益明细页有「按月切换」Tab。当前前端用 `overview.monthlyTrend`（**仅本年 1—12 月**）中金额 >0 的月份 + 当前月推导 Tab。**跨年历史收益（如 2025-12）永远不会出现在 Tab 里**，但 `/earnings` 按该月查询实际有数据 —— 数据可达但入口缺失。

**建议**（二选一）：
1. 新增 `GET /publisher/settlement/earnings/months` → `data: ["2026-06", "2026-05", ..., "2025-12"]`（有收益记录的月份，降序）；
2. 或 `overview` 增加 `availableMonths` 字段。

## 二、缺字段 / 字段口径问题

### P1-3. `viewCount` 为累计值，与「按日 × 剧」行粒度不匹配

契约 20260701 已注明：`viewCount` 取 `course.view_counts` 累计播放量，同一剧多日行重复展示同一数值。设计意图上「播放量」列在按日行中更合理的是**当日增量**。本期前端按契约照实展示，但用户可能质疑「每天播放量一样」。

**建议**：后续版本接入 watch 按日聚合，行内改为当日播放量（或增加 `dailyViewCount` 字段并保留累计值）。请排期确认。

### P2-4. `/publisher/member/list` 无分页

契约返回全量数组。成员数可控（一般 <50）问题不大，但请确认后端是否有上限保护；若未来放开成员数，需补 `page/limit`。前端当前按全量渲染。

### P2-5. `/publisher/member/add` 成功响应 `data` 未定义

契约未写明 add 成功后 `data` 返回什么。前端当前只依赖 `code=0` 后重新拉列表。若能直接返回新成员实体（同 list 行结构），可省一次列表请求。低优先级。
