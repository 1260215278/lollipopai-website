## 一、新版上剧文档消费结论

`docs/0704/发行中心-上剧全流程-前端对接-20260703 (1).md` 新增了 Step1「类别」：

- 新接口：`GET /publisher/course/classifications?languageType=<语言code>`
- `saveBasic` 新增字段：`classificationId`
- 草稿回显：`data.course.classificationId` / `classificationName`
- 发布兜底：未选类别时 `publish` 返回 `publisher_course_basic_incomplete`
- 无效类别：`publisher_course_classification_invalid`

这部分契约整体可用，前端不需要再写死「真人剧 / AI短剧」，会从候选接口读取。

## P0. 账号短信 `scene` 枚举仍缺明确契约

### 现状

账号契约只写：

```http
GET /publisher/account/sendSmsCode?scene=
```

但没有说明 `scene` 的允许值。账号中心设计涉及：

- 未设置密码时，通过短信设置新密码。
- 两步验证启用。
- 两步验证关闭。
- 注销账号短信再鉴权。

### 前端影响

前端不能猜 `scene=changePassword` / `twoFactor` / `cancel` 这类字符串，否则后端真实枚举不同会直接联调失败。

### 建议后端补充

请明确：

| scene | 用途 | 后续接口 |
|---|---|---|
| `change_password` | 未设置密码时设置新密码 | POST `/publisher/account/changePassword` |
| `two_factor_enable` | 启用两步验证 | POST `/publisher/account/twoFactor/enable` |
| `two_factor_disable` | 关闭两步验证 | POST `/publisher/account/twoFactor/disable` |
| `cancel_account` | 注销账号 | POST `/publisher/account/cancel` |

同时确认：

- 验证码发到当前成员绑定手机号，还是发行账户主账号手机号。
- 当前成员无绑定手机号时错误码。
- `scene` 非法时错误码。
- 频控、有效期、重复发送是否覆盖旧码。
- `changePassword` 在 `passwordSet=true` 时是否允许短信码替代旧密码。

## P1. 顶部账号信息展示字段不足

### 现状

设计稿顶部用户区需要展示类似：

```text
12****5674
出品方
```

`/publisher/member/me` 目前主要满足权限控制：

```json
{
  "memberUserId": 10001,
  "role": 2,
  "roleName": "管理员",
  "permissions": ["dashboard", "course", "settlement_view"]
}
```

账号聚合接口 `/publisher/account/info` 虽有 `profile/contact`，但文档注明仅超管可用，不能作为管理员/员工通用顶部信息来源。

### 建议后端补充

建议扩展 `GET /publisher/member/me`：

```json
{
  "memberUserId": 10001,
  "role": 2,
  "roleName": "管理员",
  "permissions": ["dashboard", "course", "settlement_view"],
  "nickname": "运营管理员",
  "avatar": "https://oss.example/avatar.png",
  "phoneMask": "12****5674",
  "publisherName": "北京星河文化传媒有限公司"
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `nickname` | string | 当前登录成员昵称；无昵称时返回可展示账号名或空字符串 |
| `avatar` | string \| null | 当前登录成员头像 |
| `phoneMask` | string \| null | 当前登录成员手机号掩码，与成员列表口径一致 |
| `publisherName` | string \| null | 发行方/出品方名称 |

## P1. 上剧详情页类别回显字段需确认

### 现状

新版文档明确：

- 草稿 `draft.data.course` 返回 `classificationId` / `classificationName`。
- Step1 保存提交 `classificationId`。

但 `GET /publisher/course/detail` 的 `basic` 描述仍是：

```text
封面/简介/集数/频道/标签/版权/语言 + createTime + 高光四字段
```

没有明确详情接口是否返回类别字段。

### 前端影响

如果详情页需要展示「类别」，前端需要稳定字段，不能从草稿接口或类别候选接口反推。

### 建议后端补充

请确认 `GET /publisher/course/detail` 是否在 `data.basic` 中返回：

```json
{
  "classificationId": 11,
  "classificationName": "真人剧"
}
```

如果产品确认详情页不展示类别，也请在契约里注明「详情页不返回/不展示类别」，前端按此处理。

## P1. 收益明细跨年月份入口仍缺

### 现状

`GET /publisher/settlement/overview.monthlyTrend` 已改为本年 1-12 月固定 12 项。  
这能满足当年图表，但无法覆盖跨年历史月份入口。

例如：`/publisher/settlement/earnings` 查询 `2025-12` 有数据，但月份 Tab 只能从本年趋势推导，用户无法点到 2025-12。

### 建议后端补充

二选一：

1. 新增 `GET /publisher/settlement/earnings/months`：

```json
["2026-06", "2026-05", "2025-12"]
```

2. 或在 `GET /publisher/settlement/overview` 增加：

```json
{
  "availableMonths": ["2026-06", "2026-05", "2025-12"]
}
```

## P1. 收益明细播放量口径需后续排期确认

### 现状

`GET /publisher/settlement/earnings` 的 `viewCount` 当前契约是 `course.view_counts` 累计播放量。  
收益明细行粒度是「按日 × 剧」，同一剧多日行会显示同一个累计播放量。

### 建议

如果产品希望「播放量」列符合当日收益行粒度，建议后续增加：

```json
{
  "dailyViewCount": 1234,
  "viewCount": 1123000
}
```

前端可展示 `dailyViewCount`，必要时 tooltip 展示累计 `viewCount`。

## P2. 成员列表与添加成员响应优化

### P2-1. `/publisher/member/list` 是否需要分页或上限保护

当前契约返回全量数组。成员数较小时前端可接受，但请确认后端是否有上限保护。  
如果未来成员数可能放开，建议补 `page/limit`。

### P2-2. `/publisher/member/add` 成功响应体未定义

当前前端只依赖 `code=0`，成功后重新拉列表。  
如果后端方便，可返回新增成员实体，结构同成员列表单行：

```json
{
  "memberUserId": 10002,
  "nickname": "运营管理员",
  "avatar": null,
  "phoneMask": "139****6688",
  "role": 2,
  "roleName": "管理员",
  "status": 1,
  "statusName": "使用中",
  "self": false,
  "removable": true,
  "joinTime": "2026-07-04 10:00:00"
```

此项不阻塞前端。
