## 五、根因与机理

旧构建（canonical/sitemap 带 `/lollipop/` 前缀）曾长期在线，Google 已抓取并索引约 850+ 条遗留 `/lollipop/*` 与重复 URL。09-11 部署干净构建后：
- 新 sitemap 仅 372 条干净根 URL（已正确提交）；
- 遗留 `/lollipop/*` 现统一服务首页、canonical 指向首页，Google 不再单独收录（归类为「备用网页」/「自动重定向」）。

这些遗留分类属 **Google 重抓前的滞后快照**，需等 Google 重新抓取 372 条干净 URL 后逐步清零，**不是新的结构性缺陷**。

1. **监控**：未来 2–4 周观察 GSC「自动重定向 / 备用网页 / noindex」三类是否向 0 收敛；预期随重抓回落。
2. **IndexNow**：key `fc327f494d3f4612b851a2972530d549` 已在 `public/`。可向 IndexNow API 提交 372 条干净 URL 加速 Bing/Yandex 等发现（注：Google 不消费 IndexNow，对 GSC 无直接影响）。
3. **GSC 主动请求收录**：对首页、`/about`、`/blog`、Top 文章用「网址检查 → 请求编入索引」提速（Google 无批量 API，仅单条）。
4. **可选 301 退役遗留 URL**：在 Cloudflare 配 Bulk Redirect `/lollipop/*` → `/$1`，让约 298 条遗留 URL 干净 301 到对应根 URL，比当前「服务首页」更快清零「备用网页」并释放抓取预算。当前「服务首页 + canonical=首页」亦可接受、无害。
