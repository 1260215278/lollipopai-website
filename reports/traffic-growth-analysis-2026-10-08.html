二、根因深度分析

问题 1：尾部斜杠双重重定向链（969 页）P0

969 个页面因重定向链被 Google 拒绝索引 CRITICAL

根因：Cloudflare 对所有不带尾部斜杠的 URL 自动添加斜杠，同时将协议从 HTTPS 降级为 HTTP，导致每个 URL 经历两次 301 重定向。

请求: https://www.lollipop.im/blog/ai-short-drama-pillar-guide (sitemap 中的 URL，无斜杠)
→ 第1跳 301 Location: http://www.lollipop.im/blog/ai-short-drama-pillar-guide/ (加了斜杠 + 降级为HTTP!)
→ 第2跳 301 Location: https://www.lollipop.im/blog/ai-short-drama-pillar-guide/ (HTTP升回HTTPS)
→ 最终 200 返回页面内容

影响范围：sitemap.xml 中 564 个 URL 中有 558 个不带斜杠，全部受影响。加上 Google 通过 hreflang、内部链接发现的额外 URL，总计 969 个页面。

Google 的处理方式：Googlebot 遵循重定向但不会索引经过多次重定向的页面，直接标记为"网页会自动重定向"错误。

根因定位：Cloudflare 的 SSL/TLS 加密模式可能为 "Flexible"（灵活），导致 Cloudflare 到源站使用 HTTP，返回的 Location 头也使用 HTTP 协议。

问题 2：生产域名服务旧版本内容P0

www.lollipop.im 服务的是 9 月 2 日的部署，最新内容只在 IP 上可访问 CRITICAL

发现：服务器上存在两个不同步的部署目录：

目录 最后修改 服务域名 index.html 大小
/var/www/lollipop 2026-09-02 www.lollipop.im (生产域名) 223 KB
/srv/www/lollipop/current 2026-10-07 43.160.226.253 (IP) 148 KB

影响：Caddy 配置中 www.lollipop.im 域名的 root 指向 /var/www/lollipop（旧目录），Google 看到的内容比实际最新内容滞后一个多月。新增的 9 篇文章、SEO 修复、封面图等优化全部未生效。

修复：更新 Caddy 配置，将 www.lollipop.im 的 root 改为 /srv/www/lollipop/current，或将新部署同步到 /var/www/lollipop。

问题 3：235 个页面被 noindex 排除P1

235 个页面被 noindex 标记排除索引 HIGH

已知 noindex 页面（6 个）：

  • /login/index.html - noindex, follow（正确配置）
  • /forgot-password/index.html - noindex, follow（正确配置）
  • /yandex_*.html - 验证文件
  • /_redirects - Netlify 重定向规则文件

推测：实际只有 6 个文件包含 noindex 标签，但 GSC 报告 235 个。可能原因：

  • 多语言版本（/zh/login/, /pt/login/ 等 5 种语言 × 2 页面 = 10 个额外页面）
  • 旧部署目录 /var/www/lollipop 中可能存在更多 noindex 页面
  • Google 缓存了已删除但曾经存在 noindex 的页面
  • SPA 路由产生的动态 noindex（React Router 的某些路由可能包含 noindex）

问题 4：130 个备用页面（canonical 指向问题）P1

130 个页面被标记为备用页面 HIGH

问题：canonical 标签使用不带尾部斜杠的 URL，但实际服务的 URL 带尾部斜杠。canonical 指向的 URL 本身会 301 重定向，导致 Google 无法正确解析规范页面。

HTML 中的 canonical: <link rel="canonical" href="https://www.lollipop.im/blog/ai-short-drama-pillar-guide" />
→ 但该 URL 301 重定向到带斜杠版本
Google 看到的: "这个 canonical 指向一个重定向 URL，标记为备用页面"

问题 5：语言变体重定向不一致P1

/zh/* 和 /pt/* 重定向到查询参数格式 HIGH

不同语言路径的重定向行为不一致：

URL重定向到问题
/zh/about→ /about/?lang=zh-CNURL 结构改变
/pt/about→ /about/?lang=ptURL 结构改变
/es/about→ /es/about/仅加斜杠（正常）
/ar/about→ /ar/about/仅加斜杠（正常）

文件实际存在但 Cloudflare 页面规则将 /zh/* 和 /pt/* 导向了错误的 URL 格式。

问题 6：510 个 HTML 文件引用旧 /lollipop/ 前缀P2

510 个 HTML 文件的 favicon 等资源链接仍使用 /lollipop/ 前缀 MEDIUM

首页已修复，但子页面（genre 页、region 页、privacy 等）仍包含：

<link rel="icon" href="/lollipop/favicon-32.png" />
<link rel="icon" href="/lollipop/favicon.png" />

这些路径会经历 301 重定向（/lollipop/ → /），增加额外的重定向负担。

三、修复方案（按优先级排序）

P0 - 立即修复（影响 969 + 全部页面）
  1. 修复 Cloudflare SSL 模式：登录 Cloudflare → SSL/TLS → 将加密模式从 "Flexible" 改为 "Full (Strict)"，确保 Cloudflare 到源站使用 HTTPS，消除 HTTPS→HTTP→HTTPS 双重重定向链。
  2. 同步生产部署目录：将 Caddy 配置中 www.lollipop.im 的 root 从 /var/www/lollipop 改为 /srv/www/lollipop/current，确保 Google 看到最新内容。
  3. 统一 URL 格式：在 sitemap.xml 和 canonical 标签中将所有 URL 改为带尾部斜杠格式，与实际服务 URL 一致。或者反向操作：配置 Caddy 禁止自动添加尾部斜杠。
P1 - 尽快修复（影响 365 页面）
  1. 修复 Cloudflare 语言页面规则：删除 /zh/* 和 /pt/* 的特殊页面规则，确保所有语言路径统一使用路径前缀格式。
  2. 清理 noindex 标签：检查旧部署目录中是否有多余的 noindex 页面，确保只有 /login 和 /forgot-password 使用 noindex。
  3. 验证 canonical 一致性：确保 canonical URL 与实际服务 URL 一致（都带斜杠或都不带斜杠）。
P2 - 计划修复（影响 510 页面）
  1. 修复 /lollipop/ 旧前缀：重新构建或批量替换 510 个 HTML 文件中的 /lollipop/ 路径。
  2. 补充 blog.ts 缺失字段：5 篇文章缺少 coverImage，4 篇缺少 author/excerpt/seoTitle/seoDescription。
  3. 提交 GSC 重新验证：修复后在 GSC 中点击"验证修复"按钮，加速 Google 重新抓取。
