# 发行中心-结算管理 & 收款信息 前端对接（2026-07-04，综合版·自包含）

覆盖两个页面：发行中心控制台 → 收益中心 → **结算管理**（§1-§6，含申请确认弹窗/详情弹窗/按时间与按剧集图表/已提交与重新提交态）、**收款信息**（§7，多卡+默认卡）。本文档自包含，直接转发前端即可。

- Base：`https://admin.testshort.top/sqx_fast`（test 环境）
- 鉴权：请求头 `token` = 发行中心 token（`POST /publisher/login/byAppToken` 换取）
- 响应统一：`{"code":0,"msg":"success","data":...}`；`code!=0` 时 `msg` 为已翻译的错误文案（按 App 语言头）
- **金额一律 CNY（¥）**：后端已按支付日汇率逐单转换入库，前端不做任何汇率换算

## 展示约定（先读这段）

| 字段 | 约定 |
|---|---|
| `status` | 1=已申请(待审核) 2=审核通过(待打款) 3=已打款 4=驳回/打款失败 |
| `statusGroup` | 三态徽标直接用它：`applied`(1,2)→「已申请」/ `settled`(3)→「已结算」/ `failed`(4)→「结算失败」 |
| `publishScope` | 1=账号主页订阅、2=全量推荐订阅（名称前端多语言自备） |
| `ratioLabel` | **「平台:出品方」方向**，直接展示：`"2:8"`（主页）/`"4:6"`（全量）/`"mixed"`（周期内比例变过，罕见） |
| 「结算日期」列 | `statusGroup==='settled'` 显示 `payTime`，否则显示 `applyTime` |
| 「结算说明」卡片 | 文案（每月15日出款/审核1-3个工作日）前端静态多语言，不出接口 |
| 失败原因 | `auditRemark`（详情弹窗展示） |

## 1. 概况+按钮可用性

`GET /publisher/settlement/summary`

```json
{
  "hasPayoutAccount": true,
  "canApply": true,
  "resubmit": false,
  "blockReason": null,
  "totalSettledCny": 10462.50,
  "settledCount": 3,
  "pendingMonths": ["2026-06"],
  "pendingTotalCny": 3360.00,
  "payoutAccount": { "bank": "中国建设银行", "accountNoMasked": "****1234" },
  "currency": "CNY"
}
```

- 「提交结算申请」按钮：`canApply=false` 置灰；`blockReason` 枚举决定按钮态：
  - `NO_PAYOUT_ACCOUNT` → 置灰，按钮下方小字"请先添加收款账户"（空态页）
  - `ALREADY_APPLIED_THIS_MONTH` → 按钮自身换成「✓ 本月已提交申请」灰态（「已提交」页）
  - `NO_SETTLEABLE_EARNINGS` → 置灰，提示暂无可结算收益
  - `null` → 黑色可点击态；此时再看 `resubmit`：`true`（本月有被拒申请）→ 按钮文案「重新提交结算申请」，`false` → 「提交结算申请」。申请通过后本月不会再出现可点击按钮（走 ALREADY_APPLIED_THIS_MONTH 灰态）
- 「累计结算 ¥10,462.50」= `totalSettledCny`；「已结算 3笔」= `settledCount`
- **申请确认弹窗**（点按钮后、确认前展示）三行同样取自本接口：
  - 结算周期 = `pendingMonths`（单月直接显示，多月用「、」连接或显示区间）
  - 可结算金额 = `pendingTotalCny`（¥）
  - 收款账户 = `payoutAccount.bank + ' ' + payoutAccount.accountNoMasked`（未绑账号时为 null）
  - 「确认提交」→ 接口 2；提示文案（审核 1-3 工作日、15 日前打款）前端静态多语言

## 2. 提交结算申请

`POST /publisher/settlement/apply`（无 body；**仅超管角色**，成员无此权限）

规则：把截至上月末所有未结算的完整自然月，按「月×结算类型」逐条生成结算单；一个自然月只能成功提交一次；失败(结算失败)的可重新申请（生成新单号，旧单保留展示）。

成功 `data`（本次生成的单）：

```json
[
  { "orderNo": "ORD-20260704-001", "periodMonth": "2026-05", "publishScope": 2, "ratioLabel": "4:6", "creatorCny": 860.20 }
]
```

错误码：`403368` 未绑收款账户 / `403369` 本月已提交过 / `403370` 暂无可结收益（msg 已翻译，直接 toast）。

## 3. 结算记录列表

`GET /publisher/settlement/records?status=&keyword=&scope=&page=1&limit=10`

- `status` 可空，取原始状态 1/2/3/4。UI「结算状态」下拉建议映射：全部→不传、已申请→1、打款中→2、已结算→3、结算失败→4（若产品坚持三态下拉，把 1 和 2 合并为「已申请」时需分别请求或改用不传 status + 前端按 `statusGroup` 过滤，建议直接用四态）
- `keyword`：匹配 订单编号 / 结算周期（如 `2026-05`）
- `scope` 可空：1/2

`data` 为标准分页对象 `{totalCount, pageSize, totalPage, currPage, list}`，行：

```json
{
  "id": 5,
  "orderNo": "ORD-20260610-002",
  "periodMonth": "2026-05",
  "publishScope": 2,
  "ratioLabel": "4:6",
  "creatorCny": 1200.00,
  "status": 1,
  "statusGroup": "applied",
  "auditRemark": null,
  "applyTime": "2026-06-10 10:00:00",
  "payTime": null,
  "accountNoMasked": "****4567"
}
```

## 4. 结算单详情（操作列「详情」）

`GET /publisher/settlement/records/{id}`

`data` = 列表行全部字段 +：

```json
{
  "grossCny": 2000.00,
  "platformCny": 800.00,
  "creatorUsd": 176.80,
  "rateSnapshot": 6.7907,
  "accountSnapshot": "{\"companyName\":\"...\",\"accountNo\":\"6222...4567\",\"bank\":\"...\",\"branch\":\"...\",\"accountHolder\":\"...\",\"currency\":\"USD\"}",
  "auditTime": "2026-06-11 09:00:00",
  "payVoucherUrl": null,
  "items": [
    { "courseId": 101, "periodMonth": "2026-05", "publishScope": 2, "orderCount": 12,
      "grossUsd": 200.00, "creatorUsd": 120.00, "grossCny": 1358.14, "creatorCny": 814.88 }
  ]
}
```

`accountSnapshot` 是 JSON 字符串（申请时点的收款账号快照），前端 `JSON.parse` 后展示。时间线：`applyTime` 申请 → `auditTime` 审核 → `payTime` 打款。

**「详情」弹窗字段映射**（已结算/结算失败两态同一弹窗）：

| 弹窗行 | 字段 |
|---|---|
| 申请编号 | `orderNo`（后端统一 `ORD-` 前缀；设计稿弹窗里的 `APP-` 与列表 `ORD-` 不一致，以 `ORD-` 为准） |
| 申请时间 | `applyTime`（含时分） |
| 结算周期 | `periodMonth` |
| 收款账户 | `JSON.parse(accountSnapshot).bank + ' ' + accountNoMasked` |
| 申请金额 | `creatorCny`（¥） |
| 申请状态 | `statusGroup` 三态徽标（applied/settled/failed） |
| 拒绝原因（红框，仅 failed） | `auditRemark` |

## 5. 结算概况图表（按月按剧）

`GET /publisher/settlement/chart?startMonth=2026-01&endMonth=2026-06&courseIds=101,102,103`

- 三参均可空：默认近 6 个自然月、剧集默认取累计结算额 Top3
- 口径：**已结算（status=3）** 的结算单按剧明细
- 「对比剧集」chips 增删 → 改 `courseIds` 重新请求；「选择剧集」下拉数据源见接口 6

```json
{
  "months": ["2026-01", "2026-02", "2026-03", "2026-04", "2026-05", "2026-06"],
  "series": [
    { "courseId": 101, "courseName": "星河恋人", "points": [0, 0, 1250.00, 1650.00, 2200.00, 0],
      "totalCny": 5100.00, "cumulativeCny": 5100.00 }
  ]
}
```

- **按时间**视图（折线）：每个 series 一条线，x 轴 = `months`，y = `points`（范围内按月金额）
- **按剧集**视图（横向条形，"各剧集累计结算总额"）：用 `series[].cumulativeCny` —— **全期累计**，不受 startMonth/endMonth 限制；series 已按 cumulativeCny 倒序。注意区分：`totalCny`=请求月份范围内合计（配合折线），`cumulativeCny`=全期累计（配合条形图）
- 选中的剧集即使在当前月份范围内没有结算（points 全 0）也会出现在 series 里（条形图仍有值）
- 卡片右上「累计结算/已结算N笔」用接口 1 的 `totalSettledCny`/`settledCount`

## 7. 收款信息页（多卡模型，结算前置）

一个出品方可添加多张对公银行卡，**一张默认卡**（结算申请/打款代入默认卡，即结算弹窗和 summary.payoutAccount 展示的那张）。均为超管权限（成员无）。

| 接口 | 说明 |
|---|---|
| `GET /publisher/payout/account/list` | 卡片列表。`data: { companyName, list: [vo...] }`，默认卡在前；`list` 为空 → 空态页；`companyName` 供「新增收款账户」表单只读自动带入 |
| `POST /publisher/payout/account` | 新增：body `{accountNo(纯数字必填), bank(必填), branch?, isDefault?}`。**公司名服务端按入驻资料回填，前端不传**；首张卡自动默认；`isDefault:true` 直接设为默认。重复卡号报 `403373` |
| `POST /publisher/payout/account/update` | 编辑：同上 + `id`（必传）。不存在/不属于本账户报 `403316` |
| `POST /publisher/payout/account/delete` | 删除：body `{id}`。**删除默认卡时后端自动把最近添加的一张提升为默认**；删光后结算按钮自然禁用 |
| `POST /publisher/payout/account/setDefault` | 设为默认：body `{id}` |
| `GET /publisher/payout/account` | 默认卡视图（兼容/表单带入用），`data.bound=false` 表示还没有卡 |

卡片 vo 字段：`{id, companyName, accountNo, bank, branch, isDefault(1=默认), status, createTime, updateTime}`。
卡号脱敏展示（`3455 **** **** 1456`）由前端处理（自己的卡返回完整卡号，编辑表单要用）。
黄条提示（仅支持对公账户、打款至默认账户）前端静态多语言。

## 流转参考（联调用）

1. 绑收款账号 → `summary.canApply=true`（有可结月份时）
2. `POST /apply` → 生成 status=1 的单（列表徽标「已申请」）
3. 后管（发行者中心→结算审核 tab）通过 → status=2（徽标仍「已申请」）
4. 后管标记打款成功 → status=3「已结算」，`payTime`/`payVoucherUrl` 落值，图表出数据
5. 后管驳回或打款失败 → status=4「结算失败」（`auditRemark`=原因），本月可重新申请
