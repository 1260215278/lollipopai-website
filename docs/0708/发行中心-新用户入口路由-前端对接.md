# 发行中心「新用户入口」路由修复 — 前端对接

> 适用范围：发行中心控制台前端（`www.lollipop.in/distribution/**`，独立仓，不在后端工作区）。
> 后端与 `/app/publisher/status` 均已就绪，**本次为纯前端改动，后端无需改动**。
> 文档日期：2026-07-08

## 一句话根因

新账号点「发行中心」时，控制台入口守卫调 `POST /publisher/login/byAppToken`，后端查不到该用户的启用中成员记录 → 按设计返回 `40020（没有权限）`。前端把这个失败**直接弹窗把用户堵死**了，而没有把"从未入驻的新用户"导向**入驻申请页**。

`byAppToken` 对新用户返回 40020 是**后端正确设计**（控制台只给"已入驻/成员"进）。前端缺的分支是：**登录失败后回落到入驻状态判断，把新用户导去入驻申请页**。

> 复现账号：`+1 2175285111`（user_id=185137，昨天注册），`is_publisher=0`、无 `publisher_member`、无 `publisher_apply` —— 彻头彻尾的新号，正确行为应直达入驻申请表单。

> 背景：这大概率是上次修「成员进不了工作台」时，把入口守卫从"按 is_publisher 判定"改成"byAppToken-first"引入的回归 —— 补上"失败回落 status"这条分支即可。

## 正确的入口流程（伪代码）

在进入 `/distribution/**`（点"发行中心"）的路由守卫里：

```js
// 1) 先尝试控制台登录
const r = await POST('/publisher/login/byAppToken', { appToken });  // 也可用 header token

// 2) 成功：注意 2FA 分支——成功时 code 仍是 0，要看 stage
if (r.code === 0) {
  if (r.stage === '2FA_REQUIRED') { goTo2FA(r.data); return; }   // data: {challengeToken, phoneMask, expireSeconds}
  savePublisherToken(r.data);      // data 是 publisherToken 字符串
  enterConsole(); return;
}

// 3) 失败（code=500，任意 msg）：不要弹窗堵死！回落到入驻状态判断
const s = await GET('/app/publisher/status');   // header token = App token
// App token 已失效 → 走全局 401 → 重新登录（与 App 其它接口同一套）
const { auditStatus, isPublisher } = s.data;

if (auditStatus === null)       goEnrollForm();                   // 从未申请 → 入驻申请表单  ★本次用户的情况
else if (auditStatus === 0)     goUnderReview();                  // 审核中
else if (auditStatus === 2)     goRejected(s.data.rejectReason); // 已驳回，可重提
else if (auditStatus === 1)     handleApprovedButBlocked(r.msg); // 已通过但登录被拒(多为账户停用403347) → 展示 r.msg
else                            goEnrollForm();                   // 兜底
```

### 为什么"失败即回落 status"能覆盖全部情况（无需区分是不是 40020）

| 用户类型 | byAppToken | 随后 status | 结果 |
|---|---|---|---|
| 新用户（本次）is_publisher=0/无成员/无申请 | 500(40020) | auditStatus=null | → **入驻申请页** ✅ |
| 已入驻成员（被邀请，is_publisher=0 但有成员记录） | code=0 拿到 token | —— | → 进控制台 ✅ |
| 出品方主账号（已通过） | code=0 | —— | → 进控制台 ✅ |
| 申请审核中 | 500(40020) | auditStatus=0 | → 审核中页 ✅ |
| 申请被驳回 | 500(40020) | auditStatus=2 | → 驳回页可重提 ✅ |
| 账户被停用 | 500(403347) | isPublisher=1/auditStatus=1 | → 展示"账户已停用"文案 ✅ |
| App token 过期 | 500(401182) | 401 | → 重新登录 ✅ |

> 之所以"成员进控制台、新用户去入驻"这两件看似冲突的事都能对，是因为**唯一能区分"成员 vs 全新用户"的信号在 `publisher_member` 表，只有 `byAppToken` 会查**。`/app/publisher/status` 只看 `publisher_apply`/`is_publisher`，对成员也会返回 `auditStatus=null`，所以**必须"byAppToken 优先、失败再看 status"**，不能只靠 status。

## 接口契约（精确响应结构）

### ① `POST /publisher/login/byAppToken`
参数 `appToken`（或 header `token` = App token）

```jsonc
// 成功(无2FA)
{ "code": 0, "msg": "success", "data": "<publisherToken 字符串>" }

// 成功但需二次验证 —— 注意 code 仍是 0！必须判 stage
{ "code": 0, "msg": "success", "stage": "2FA_REQUIRED",
  "data": { "challengeToken": "...", "phoneMask": "138****1234", "expireSeconds": 300 } }

// 失败(全部 code=500，仅 msg 文案不同) —— 前端不要 toast 后终止，需回落 status
{ "code": 500, "msg": "没有权限，请联系管理员授权" }   // 40020: 非成员/新用户
{ "code": 500, "msg": "..." }  // 401181未登录 / 401182登录失效 / 403347账户已停用
```

⚠️ **坑**：`code` 对所有失败都是 `500`，`40020`/`403347` 等只是查 `msg` 的 i18n key，**不会出现在响应字段里**，别用 `code` 去判具体错误。区分逻辑一律走"失败 → 回落 `/app/publisher/status`"。

### ② `GET /app/publisher/status`
header `token` = App token（`@Login`）

```jsonc
{ "code": 0, "msg": "success",
  "data": {
    "auditStatus": null,      // null=未申请 / 0=待审 / 1=通过 / 2=驳回
    "rejectReason": null,     // 驳回原因(auditStatus=2 时)
    "isPublisher": 0,         // 0/1，来自 tb_user
    "apply": null             // 申请记录对象，未申请为 null
  } }
```

## 入驻申请页用到的接口（新用户导过去之后）

- `GET /app/publisher/sendCode?phone=xxx`（或 `email=xxx`）— 发入驻验证码，免登录
- `POST /app/publisher/submit` — 提交/重提入驻申请（免登录；已登录带 App token 保持原逻辑）
- 图片/资质上传复用 `POST /alioss/upload`（multipart `file`，URL 在响应 `data`）
